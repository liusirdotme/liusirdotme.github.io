计算机软件著作权

发表于 2026-07-06 分类于 Book 3.7k 3 分钟

软著全称是‌计算机软件著作权‌，是指自然人、法人或其他组织对计算机软件作品享有的财产权利和精神权利的总称。它保护的是你开发的软件程序及相关文档。‌‌

申请流程

一、前期准备：材料清单（必带）

1. 主体身份证明

  • 个人申请：身份证正反面清晰PDF；非职务开发说明（自由职业/学生必备）
  • 企业申请：营业执照副本PDF（加盖公章扫描）；法人信息
  • 合作/委托开发：合作协议、委托开发合同、权属说明（全体权利人签字盖章）

2. 软件鉴别材料（审核核心）

  1. 源代码PDF
    程序前后各连续30页，每页≥50行代码；总代码不足60页则全部上传；剔除注释空行，保留核心业务代码。
  2. 配套文档PDF（二选一）
    软件使用说明书 / 设计说明书，图文结合，每页≥30行文字，至少15页。

3. 申请表（系统生成，无需自制）

线上填完信息后导出打印，个人手写签名、企业加盖公章，再扫描PDF上传系统。

4. 特殊补充材料

含开源框架：开源协议+自有代码区分说明；升级版本：前一版软著证书复印件。

二、线上完整操作步骤（自助办理）

步骤1：注册账号并实名认证

  1. 官网，右上角【注册】，选择个人/机构账号
  2. 手机号验证、设置密码完成注册
  3. 进入账户中心提交实名认证：
    • 个人：上传身份证
    • 企业：上传营业执照、法人信息
      实名审核一般1个工作日内通过

步骤2：发起软著登记业务（R11计算机软件著作权登记）

  1. 首页进入【软件著作权相关登记】，选择 R11 计算机软件著作权登记申请
  2. 身份选择：本人申请选【申请人】，代办选【代理人】

步骤3：在线填写申请信息

按页面分栏完整填写，信息必须与材料完全一致：

  1. 软件基础：全称（必须带XX软件/系统V1.0）、版本号、开发完成日期、发表状态
  2. 开发信息：编程语言、运行环境、硬件环境、软件功能简介
  3. 权属信息：独立开发/委托/合作/受让，权利范围（全部/部分）
  4. 申请人、联系人、收证地址

步骤4：上传全部PDF材料

按系统分类上传，全部文件仅支持PDF，单文件不超20M：

  1. 签章后的申请表扫描件
  2. 身份证/营业执照
  3. 源代码鉴别材料
  4. 软件说明书
  5. 权属协议、开源说明等补充文件

步骤5：提交申请、等待受理

  1. 核对全部信息，提交生成受理流水号
  2. 系统初审材料完整性，符合要求即正式受理；材料缺失直接驳回
  3. 审核期间站内信通知进度，有问题下发补正通知书，需30日内修改重传，超时视为撤回申请

三、审核、下证与取证

  1. 审核周期
    • 普通通道：受理后 30–45个工作日
    • 无官方免费加急，加急仅第三方代理渠道
  2. 登记公告
    审核通过后进行版权登记公告，公示无异议完成登记
  3. 领取证书（2种）
    • 电子证书（推荐，免费）：用户中心-我的登记直接下载PDF，带官方电子签章，招投标、高新、双软均有效，支持线上验签
    • 纸质证书：申请邮寄，邮费到付；也可线下大厅自取

四、两种办理方式对比

方式 优点 缺点 适用人群
自助线上办理 无服务费，成本最低，全程自己可控 需自行整理代码、说明书，不懂规范易补正 懂基础文档整理、时间充裕企业/个人
委托代理办理 代理代写材料、规避补正、跟进进度 收取服务费 加急、不会整理源码说明书、没时间操作

五、常见驳回/补正关键点

  1. 软件名称不规范：不能纯英文、不能不带“软件/系统”后缀
  2. 源代码行数不足、大量空行注释、前后页数不连续
  3. 说明书页数太少、无截图、功能描述和申请表不一致
  4. 申请表未盖章/签名、扫描模糊、格式篡改
  5. 权属矛盾：合作开发缺少全体权利人授权

六、重要补充说明

  1. 登记免费：版权中心不收取登记费，仅纸质证书邮寄产生快递费
  2. 著作权自动产生：软件完成创作即拥有版权，登记仅为官方凭证，不产生确权效力
  3. 证书用途：高新企业认定、双软评估、招投标、APP上架、知识产权质押、职称评定等

软著登记申请表

适用场景：中国版权保护中心线上系统填报，所有字段严格匹配审核标准，标注必填/选填/禁忌，杜绝驳回补正。

一、软件基本信息（核心必填，零容错）

字段名称 规范填写示例 填写规则&避坑要点
软件全称（必填） XX智能客户管理系统V1.0 / XX数据统计分析软件V2.1 1. 必须以软件/系统/平台/工具结尾，禁止纯英文、纯数字、通用词汇；2. 名称8-30个汉字，语义完整，体现核心功能；3. 版本号统一后缀标注，全文档保持一致
软件简称（选填） 客户管理系统 无简称直接留空，禁止填“无”“未知”；不可与全称完全重复，简洁提炼核心名称即可
版本号（必填） V1.0、V1.1、V2.0（统一大写V） 1. 首次登记统一填V1.0；2. 升级版本依次递增，禁止填写Beta、测试版、试用版等非正式版本；3. 全材料版本号必须完全一致
作品类型 计算机软件 固定选择，无需修改
开发方式（必填） 独立开发（绝大多数个人/企业选择） 合作开发/委托开发需额外上传协议；二次开发选“修改开发”，需提供原著作权授权说明
原创情况 原创软件 无借鉴、无改版选原创；基于开源框架开发仍可填原创，需备注自有核心代码

二、开发时间与发表信息

字段名称 规范填写示例 填写规则&避坑要点
开发完成日期（必填） 2026年05月20日 格式：YYYY年MM月DD日；必须早于申请日期，禁止填写未来日期
首次发表日期（选填） 未发表 / 2026年05月25日 未上线、未公开、未商用一律选未发表；仅公开发布、上架后填写具体日期

三、运行与开发环境（固定模板，直接改参数）

字段名称 通用标准模板（直接套用）
硬件环境 CPU：Intel i3及以上；内存：4GB及以上；硬盘：剩余存储空间10GB以上；支持常规台式机、笔记本及服务器设备
软件环境 支持Windows10/11、CentOS7.0及以上、Mac OS 10.15及以上操作系统，适配主流浏览器及运行环境
开发编程语言 Java / Python / PHP / C# / Vue+Java（据实填写）
程序类型 移动端APP/WEB网页端/桌面客户端/后台管理系统（据实选择）

四、主要功能与技术特点（万能通用模板，通过率100%）

1. 主要功能模板

本软件是一款面向【对应使用场景：企业办公/数据管理/用户服务/智能统计】的专业系统，核心实现数据录入、信息查询、智能统计、数据导出、权限管理、日志记录等核心功能。软件操作简洁、流程规范，可有效提升工作效率，简化业务操作流程，满足日常业务管理、数据处理及运维管控需求。

2. 技术特点模板

本软件采用主流【对应开发技术】架构开发，代码结构清晰、模块化程度高，具备良好的兼容性、稳定性与可扩展性。软件运行响应速度快、数据处理精准，支持多场景适配，安全防护完善，可适配主流软硬件运行环境，整体性能稳定，可满足长期使用及迭代升级需求。

五、申请人信息

企业申请模板

申请人名称：营业执照全称（一字不差）
统一社会信用代码：营业执照完整代码
地址：营业执照注册地址
联系人、电话、邮箱：据实填写
权属说明：独立自主开发，全部著作权归本企业所有

个人申请模板

申请人名称：本人姓名（与身份证一致）
证件号码：身份证号
住址：身份证登记地址
权属说明：个人独立开发，无任何权属纠纷，著作权归本人所有，非职务开发

源代码官方排版规范（零补正标准）

软著审核核心卡点，严格遵循版权中心要求，必须满足60页有效代码、每页行数达标、格式统一，以下为强制执行标准。

一、核心硬性审核标准

  1. 页数要求：截取软件最开头连续30页 + 最末尾连续30页；总代码不足60页的，全部完整提交，不可删减

  2. 行数要求：每页有效代码行数≥50行，剔除空行、注释行后统计，严禁行数不足

  3. 内容要求：只保留核心业务代码，删除测试代码、冗余代码、开源框架原生代码、无关配置文件

  4. 一致性要求：代码页眉软件名称、版本号，必须与申请表完全一致

二、统一排版格式（直接套用）

1. 页面基础设置

  • 纸张规格：A4纵向，单面排版

  • 字体：Consolas / 微软雅黑，小四字体，1.0倍行距

  • 页边距：上下2.5cm、左右2cm

  • 页码：右上角标注连续页码（1、2、3...），无缺失、无重复

2. 页眉规范（必加）

页眉内容：XX智能客户管理系统V1.0 源代码
规则：全程统一，无错别字、无版本偏差，所有代码页页眉完全一致

3. 代码清理规则（避坑关键）

  • 删除所有单行注释、多行注释、文档注释，仅保留可执行代码

  • 批量删除空行、换行冗余，保证页面饱满、行数达标

  • 禁止出现作者署名、开发日期、学校/企业名称等个性化信息

  • 禁止出现第三方开源版权声明，避免权属争议

三、源代码合成PDF规范

  1. 将整理好的前30页、后30页代码，按顺序合并为单个PDF文件

  2. 文件大小≤20M，无水印、无模糊、无扭曲、无多余空白页

  3. PDF命名规范：【软件全称V版本号】源代码

  4. 全程黑白打印/导出，禁止彩色页面

第三部分：高频驳回补正汇总（终极避坑）

  1. 名称违规：禁止单独使用“管理系统”“工具软件”等通用名称，必须加专属功能前缀

  2. 版本混乱：申请表、源代码、说明书版本号必须一字不差，无大小写、数字偏差

  3. 代码行数不足：空行、注释过多导致有效行数不够，直接驳回

  4. 信息矛盾：功能描述与软件名称、运行环境不匹配

  5. 签章无效：企业未加盖公章、个人未手写签名，扫描件模糊、有遮挡

第四部分：配套说明书简易规范

搭配软著申请使用，二选一提交（使用说明书/设计说明书）：

  1. 总页数≥15页，每页有效文字≥30行

  2. 包含软件简介、运行环境、安装步骤、功能截图、操作流程、故障说明

  3. 页眉、软件名称、版本号与申请表、源代码完全统一
