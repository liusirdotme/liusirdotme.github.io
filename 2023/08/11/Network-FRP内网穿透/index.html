FRP内网穿透/反向代理完整部署手册

发表于 2023-08-11 分类于 Network 5k 5 分钟

场景：公网 Linux 服务器（frps + nginx）↔ 内网 Windows 机器（frpc）
目标：让公网域名 app.example.com 访问内网 Windows 上的 Web 服务，同时可按需映射 RDP / TCP 端口。
frp 版本以 v0.61.2 为准，配置格式为 TOML（frp ≥ 0.52 已废弃 ini，老版本请自行对照字段名）。

0. 先替换这几处占位符

全文统一使用下列占位值，部署前先在你的环境里对应替换，后面不再逐处提醒。

占位符 含义 示例
1.2.3.4 公网 VPS 的 IP 47.100.x.x
app.example.com 对外访问域名（A 记录指向 VPS） oa.mycompany.com
S3cr3tT0ken... frp 认证 token，两端必须一致 32 位随机串
8080 内网 Windows 上真实 Web 服务端口 IIS 80 / PHP 8080
7000 frp 控制隧道端口 7000
8080 / 8443 frps 的 vhost 端口（仅监听本机） 8080 / 8443

1. 架构与流量走向

三个设计要点，先理解再动手，能少踩一半坑：

  1. frpc 主动外连，内网无需公网 IP、无需在路由器做端口映射，Windows 防火墙出站默认放行即可。
  2. vhost 端口必须只绑 127.0.0.1（proxyBindAddr），由 nginx 对外提供服务，防止有人绕过 nginx 直连 8080。
  3. TLS 终结在 nginx，内网应用只需跑 HTTP，证书只在 VPS 上维护一份。

2. 前置条件

  • 域名 A 记录：app.example.com → 1.2.3.4，ping 能通再继续。
  • VPS 已装 nginx，且 80/443 未被其他站点占用。
  • VPS 已放通 7000/80/443（云厂商安全组 + 系统防火墙两层都要放）。
  • Windows 侧能访问外网 7000 端口。

5. 客户端：Windows 内网机部署 frpc

5.1 下载解压

-UseBasicParsing 必加，否则部分环境因 IE 引擎未初始化而报错。

5.2 配置 C:\frp\frpc.toml

Windows 专属的三条硬规矩：

  • 文件必须是 UTF-8 无 BOM。记事本“另存为 UTF-8”会带 BOM，frpc 直接报 TOML 解析错误。用 PowerShell 落盘最稳：
  • localIP 写 127.0.0.1，不要写 localhost。Windows 上 localhost 先解析 ::1，IIS 或仅监听 IPv4 的服务会返回 connection refused。
  • 路径一律用正斜杠（C:/frp/frpc.log），或反斜杠双写（C:\\frp\\frpc.log）。

7. 上线验收清单

按顺序逐项打勾，任何一项不过就不要往下走。

  • dig +short app.example.com 返回 1.2.3.4
  • VPS：ss -lntp | grep -E "7000|8080|8443|7500" 四个端口都在
  • VPS：ss -lntp | grep 8080 的 Local Address 是 127.0.0.1，不是 0.0.0.0
  • VPS：journalctl -u frps -n 30 | grep -i login 能看到 frpc 的登录记录
  • Windows：Test-NetConnection 1.2.3.4 -Port 7000 为 True
  • Windows：Get-Service frpc 为 Running / Automatic
  • 公网：curl -I https://app.example.com 返回 200 而非 404 page not found
  • 浏览器能打开，且静态资源、接口请求均正常（无混合内容报错）
  • 业务后台里取到的客户端 IP 是真实公网 IP（验证 X-Forwarded-For 透传）
  • 重启 Windows 机器后，未登录桌面的情况下服务仍能自动起来并连通

8. 安全加固（必读）

8.1 三层防护

  1. token + TLS：已在前文配置，杜绝明文和弱认证。
  2. 端口白名单：allowPorts 限定 6000-6010，frpc 无法擅自映射其他端口。
  3. 不暴露 vhost 端口：proxyBindAddr = "127.0.0.1"，安全组也别开 8080/8443/7500。

9. 排错速查表

现象 根因 处理
域名返回纯文本 404 page not found nginx 覆盖了 Host，frps 匹配不到 customDomains 加 proxy_set_header Host $host;，然后 nginx -s reload
同上，但 Host 已正确 customDomains 域名拼写 / 与实际访问域名不一致 两端逐字符比对，含 www 与否
curl 直接超时 安全组未放通 80/443，或云厂商拦截 控制台放通，telnet 1.2.3.4 443 验证
frpc 日志 token in login doesn't match 两端 token 不一致 重取 token 覆盖两端，重启两个服务
frpc 报 TLS 握手失败 frps 开了 transport.tls.force，frpc 没开 enable frpc 加 transport.tls.enable = true
frpc connect to server error: i/o timeout 7000 未放通 / VPS 侧 frps 未启动 journalctl -u frps -n 30，Test-NetConnection
frpc 起来但代理 start error: port already used TCP 映射的 remotePort 被占 ss -lntp | grep 600X 换端口
Windows 上 connection refused localIP 用了 localhost 解析到 ::1 改 127.0.0.1，或查监听地址
上传中断 / 长任务超时 nginx 或 frp 超时过短 proxy_read_timeout 300s，client_max_body_size 调大
页面白屏、静态资源 404 内网应用按绝对 URL 拼资源，或反向代理未透传 X-Forwarded-Proto 补 X-Forwarded-Proto $scheme，应用侧信任代理头
重启后隧道不通 frpc 未装成服务，或服务以 LocalSystem 无权访问业务 Get-Service frpc，必要时改 ObjectName
frpc.exe 进程消失、日志无断连记录 Defender / 360 静默拦截 把 C:\frp 加入杀软与 Defender 排除项
nginx 502 Bad Gateway 内网服务挂了，或 frpc 掉线 先验内网直连，再看 frpc 服务状态
WebSocket 连不上（101 拿不到） 缺 Upgrade / Connection 头 补 map $http_upgrade 与两行 proxy_set_header
TOML 解析报错，配置看似正常 文件带 BOM 或用了反斜杠路径 用 UTF8Encoding($false) 重写，路径改正斜杠
日志暴涨占满 C 盘 未设日志轮转 log.maxDays = 7 + NSSM AppRotateBytes

通用定位顺序：DNS → 防火墙 → frps 登录日志 → frpc 日志 → nginx error.log → 内网服务本身，逐层往下，不要跳步。

10. 运维补充

10.1 多台内网机器 / 多个域名

frps 侧无需改动（allowPorts 与 vhost 端口通用），每台内网机各自一份 frpc.toml：

  • proxies.name 全局唯一，重复会 proxy name already exists 报错；
  • 每台机器用自己的 customDomains，nginx 里加对应 server_name 的 server 块；
  • 若域名很多，改用泛解析：frps 配 subDomainHost = "frp.example.com"，frpc 里把 customDomains 换成 subdomain = "oa"，nginx 用一个 server_name *.frp.example.com 兜住，proxy_pass 仍指向 8080 即可（Host 头保留原样，frps 自己分流）。

10.2 多服务共用 80/443

nginx 一个 server 块的 location 分流即可，但注意 frps 的 vhost 是按 Host 分流的，不能按 path 分流。路径级路由要在内网应用的网关层做，或者在内网起多个端口、frpc 起多个 [[proxies]]（不同 customDomains）。

升级前备份 /etc/frp/ 与 C:\frp\frpc.toml。跨大版本（如 0.5x → 0.6x）注意 TOML 字段有改名，先看 release notes。

10.4 带宽与并发

frp 本身不限速，瓶颈在 VPS 带宽。若业务流量大：

  • 大文件传输走对象存储直传，不要过 frp 隧道；
  • frps.toml 可加 transport.maxPoolCount = 10 提升并发隧道数；
  • nginx 侧 proxy_buffering off 已缓解流式场景的内存压力。
