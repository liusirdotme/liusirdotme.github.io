三、Linux 目录结构与文件类型

3.1 主要目录

目录 说明
/bin 二进制可执行文件（ls、cat、mkdir 等），基础命令都在这里
/sbin 系统管理类命令，多为 root 使用（ifconfig、reboot）
/etc 系统管理与配置文件
/home 普通用户主目录的基点，/home/user 可用 ~user 表示
/root root 的主目录（不在 /home 下）
/usr 系统应用程序与文件，体积最大（Unix System Resource，不是 User）
/usr/local 管理员自行安装软件的目录，推荐把自编译程序装这里
/opt 额外安装的可选应用包（Tomcat、第三方商业软件常放这）
/proc 虚拟文件系统，内存映射，读它等于读内核状态（/proc/cpuinfo、/proc/net/netstat）
/sys 同上，内核对象与设备树的映射（调参数、看 cgroup）
/dev 设备文件（/dev/vdb、/dev/null、/dev/urandom）
/mnt 临时挂载点
/media 可移动设备自动挂载点（U 盘）
/boot 引导文件（内核、grub）
/lib、/lib64 共享库与内核模块，作用类似 Windows 的 .dll
/tmp 公共临时目录，可能被清理，别放重要数据
/var 运行时变化的数据：日志（/var/log）、数据库、缓存、邮件队列
/lost+found 非正常关机后 fsck 找回的”无家可归”文件所在处（类似 Windows 的 .chk）

七、丢包、队列与防火墙

7.1 丢包先分层

读法：

  • overruns / RX dropped 涨：内核来不及取包，调 ring buffer（ethtool -G eth0 rx 4096）或看中断绑定。
  • TX dropped 涨且 txqueuelen 很小：队列太短，调大队列。
  • netstat -s 里 listening sockets overflowed 涨：应用 accept 太慢，全连接队列满，看应用 backlog 与 somaxconn。
  • 以上都干净但仍丢：mtr 看链路、tcpdump 对比进出包。

7.2 DROP 与 REJECT 的差别（一个可复现的实验）

价值在于排查时能区分两类”连不上”：

现象 含义
卡住超时、抓包只有 SYN 没回包 被 DROP / 丢包 / 安全组未放行
立刻 Connection refused 端口没监听，或被 REJECT
Connection reset by peer 建立后被 RST（服务崩了或超时断开）

清理实验规则：iptables -D INPUT -p tcp --dport 80 -j DROP（按 iptables -L --line-numbers 里的序号删更稳）。

8.3 经典案例：rm -rf 删了大文件，df 却不释放

现象与排查顺序（真实事故复盘）：

  1. 同事更新 SVN 一直失败 → 登录服务器手动 svn up 提示空间满；
  2. df -h 看到 /dev/vda1 197G 41G 197G 100% /data；
  3. 用 find . -type f -size +800M -print0 | xargs -0 ls -l | sort -nr 找到那个 300G 的大家伙；
  4. df path 确认它挂在哪个分区，rm -rf somefile 删掉；
  5. 再 df -h —— 空间没回来；
  6. lsof | grep deleted 看到还有进程（如 pid 9999）持有这个已删除的句柄；
  7. kill 9999 终止进程（服务重启），句柄释放，空间立刻回来。

原理：Linux 文件是「目录项 + inode + 数据块」，rm 只删目录项，进程开着 fd 时数据块不释放。三种解法：重启进程、> /proc/<pid>/fd/<n> 清空、或先 truncate -s 0 清内容再删。

清空正在被写的日志要用 truncate 或 : >，直接 rm 会让写日志的进程继续往已删除的 inode 里写，空间不释放（见 8.3）。

9.4 批量解压到固定目录

要点：for i in *.tgz 比 ls *.tgz 稳（后者遇到文件名带空格会被拆开）；-C 的目标目录必须已存在，否则 tar 报错。要保留每个包自己的目录结构，就按包名建子目录：mkdir -p ../tar/${i%.tgz} && tar -zxvf "$i" -C ../tar/${i%.tgz}。

9.5 批量替换与 sed

-i 不可撤销：先用 grep -c 确认匹配数量，或带 .bak 备份。

9.6 打包、解包、7z

老版本 tar（< 1.30）要求 --exclude 写在文件名之前，写在后面会被静默忽略；1.30 之后顺序不敏感。打完包用 tar -tvf 包名 | head 确认排除项没进去——这个坑不报错。

9.7 tar -zxvf xxx.gz 报 “This does not look like a tar archive”

  • 是 gzip compressed data → 纯 gzip，不是 tar.gz（日志轮转的 .gz 就是这种）：gunzip access.log.10.gz 或 zcat access.log.10.gz | less。
  • 是 gzip 仍报错 → 文件损坏，或压缩时只用了 gzip 没用 tar；先 gzip -t 校验，再从备份重取。

十一、性能分析

按「先看哪个资源到顶」的顺序排查，别一上来就盯 CPU：

资源 首选命令 看什么
CPU top / htop / vmstat 1 %us 高是业务计算，%sy 高是系统调用/上下文切换，%wa 高其实是 IO 卡住
内存 free -h / vmstat / top available 是否够；swap 是否被频繁换入换出
磁盘容量 df -h / du 是否写满，写满后很多服务直接起不来
磁盘 IO iotop / vmstat / iostat iowait、单盘吞吐与延迟
网络 iftop / iptraf / ss / nstat 带宽是否打满、连接数、丢包与队列溢出
进程 ps -ef / ps aux / top 谁吃资源、线程数、僵尸进程

负载多少算正常

经验口径：负载低于 CPU 核心数的 70% 算合理。例如 4 核，负载低于 2.8（4 × 0.7）视为正常；持续高于核数说明任务在排队，高于核数 2 倍基本就是过载。

负载统计的是「运行 + 不可中断等待」的进程数：%wa 高的机器负载会很高但 CPU 很闲——这种该查磁盘，不是换 CPU。

云主机访问不通时，先分清「机器内防火墙」还是「云平台安全组」：安全组在控制台配入方向规则，ufw/firewalld/iptables 管机器内部。两边都放行才算通。
