AWS Cloud Practitioner

备考目标不是”背服务名”，而是能在题干里认出关键词 → 对应服务 → 对应理由。CLF-C02 全是单选/多选场景题，考的是”这个场景该选谁、为什么”，不是 API 细节。

二、云概念（24%）

2.1 云的六大优势（必背，原话对应选项）

  1. 按需付费：把资本支出（CapEx）换成可变运营支出（OpEx），不用先买服务器。
  2. 规模经济：海量用户摊薄成本，单价低于自建。
  3. 不必猜测容量：按需扩容/缩容，不再为”峰值买硬件、平时闲置”买单。
  4. 速度与敏捷：资源分钟级交付，试验成本低。
  5. 轻松实现全球覆盖：一个区域部署，全球就近访问。
  6. 聚焦业务而非基础设施：把机房、运维交给云厂商。

2.2 三种服务模型 + 三种部署模型

模型 你管什么 AWS 管什么 典型服务
IaaS 基础设施即服务 OS 以上全部（系统、运行时、应用、数据） 虚拟化、硬件、机房 EC2、EBS、VPC
PaaS 平台即服务 只有应用与数据 运行时、OS、中间件 Elastic Beanstalk、RDS、Lambda（更偏 Serverless）
SaaS 软件即服务 只用，不管 全部 WorkMail、Chime、Amazon Connect、QuickSight
部署模型 含义 常见场景
Public Cloud 公有云 全部资源在 AWS 互联网业务、弹性需求
Private Cloud 私有云 资源独占（可用 Outposts 把 AWS 延伸进机房） 强合规、数据不出境
Hybrid 混合云 部分在云、部分在本地，通过 VPN/Direct Connect 打通 渐进迁移、遗留系统

2.3 七大通用设计原则（Well-Architected）

  1. 停止猜测（Stop guessing）：用数据驱动容量与架构决策。
  2. 测试驱动、自动化优先。
  3. 高可用而非”永不出错”：假设故障会发生，设计可恢复。
  4. 只做必要的复杂度。
  5. 面向未来扩展（可替换组件、解耦）。
  6. 优化成本与性能并重。
  7. 基础设施即代码（IaC）。

Well-Architected Framework 六大支柱（常考”哪个支柱管这件事”）：

支柱 管什么 关键词
运营卓越 Operational Excellence 运维流程、自动化、持续改进 runbooks、CI/CD
安全 Security 身份、数据保护、检测 least privilege、加密
可靠性 Reliability 故障恢复、备份、多 AZ Multi-AZ、RTO/RPO
性能效率 Performance Efficiency 选型、缓存、横向扩展 right instance type
成本优化 Cost Optimization 购买选项、消除浪费 Spot、Savings Plans
可持续性 Sustainability 碳足迹、能效 减少资源消耗

2.4 AWS CAF（云采用框架）六视角

视角 关注点
Business 业务 业务价值、ROI、优先级
People 人员 组织架构、培训、文化
Governance 治理 合规、预算、风险
Platform 平台 架构、环境、部署
Security 安全 身份、检测、数据保护
Operations 运营 日常运维、监控

记忆法：CAF 六视角 = 「业、人、治、台、安、运」。

2.5 迁移”7R”（原 6R + Relocate）

策略 做什么 典型场景
Rehost 重托管（Lift & Shake） 原样搬到云上 EC2 赶时间、先搬后优化
Relocate 重定位 虚拟机整体搬到 VMware Cloud on AWS 大批量 VM 平移
Replatform 重平台（Lift, Tinker & Shift） 换托管服务，如自建 MySQL → RDS 少改代码、拿托管红利
Repurchase 重购（Drop & Shop） 换用 SaaS 产品 自建 CRM → Salesforce
Refactor / Re-architect 重构 改造成云原生（微服务、Serverless） 追求弹性与性能上限
Retire 淘汰 停掉没人用的系统 降本第一刀
Retain 保留 暂不迁移 强依赖本地、合规限制

迁移与传输工具怎么选：

场景 工具
数据在线迁移（PB 级、可接受带宽） AWS DataSync、S3 Transfer Acceleration
离线大批量（TB–PB） Snowball Edge（约 80TB/台）、Snowmobile（集装箱，最高 100PB）
小批量/边缘采集 Snowcone（约 8TB）
数据库迁移（含异构） DMS（Database Migration Service）+ SCT（Schema Conversion Tool）
本地存储与云打通 Storage Gateway（File/Volume/Tape）
迁移管理编排 Migration Hub、Application Migration Service（MGN）

2.6 全球基础设施层级

层级 是什么 作用
Region 区域 地理独立的一组数据中心 数据驻留、合规、灾备
Availability Zone 可用区 区域内相互隔离的多个数据中心群（一般 3 个以上） 高可用（跨 AZ 部署）
Edge Location 边缘站点 全球数百个 CDN 节点 CloudFront 加速、Route 53
Local Zone 区域在某个大城市的延伸 低延迟本地业务
Wavelength Zone 5G 网络边缘 超低延迟移动应用
Outposts 放到客户机房的 AWS 机架 混合云、低延迟、数据不出机房

选择区域的四个因素：合规/数据驻留、与用户的地理距离、可用服务、成本。

2.7 弹性、高可用、容错（概念区分）

概念 含义 实现
弹性 Elasticity 按负载自动伸缩 Auto Scaling、Lambda 并发
高可用 HA 单点故障不影响服务 多 AZ、Multi-AZ RDS、ELB
容错 Fault Tolerance 出故障也不中断、自动切换 多区域、跨区复制
可恢复性 Resiliency 故障后能快速恢复 备份、快照、DR 方案

三、安全与合规（30%）

3.1 共担责任模型（考得最多的一题）

AWS 负责”云的安全”（Security OF the cloud），客户负责”云中的安全”（Security IN the cloud）。

层 IaaS（EC2） PaaS（RDS/Beanstalk） SaaS（如 WorkMail）
物理机房、硬件、网络 AWS AWS AWS
虚拟化层、Hypervisor AWS AWS AWS
操作系统补丁 客户 AWS AWS
中间件/数据库引擎 客户 AWS AWS
应用代码 客户 客户 AWS
数据、配置、IAM 权限 客户 客户 客户（部分）

一句话判据：只要是”数据、账号权限、代码”就是客户的；只要是”物理、虚拟化、托管服务自身的补丁”就是 AWS 的。

3.2 IAM 全套（必须能画出来）

概念 要点
User 长期身份，有固定凭证（控制台密码/access key）
Group 用户的集合，组不能嵌套组，权限按组授予
Role 临时身份，跨账号、给服务（EC2/Lambda）用、联合登录都用它，无长期密钥
Policy JSON 权限声明，Effect / Action / Resource / Condition，默认全部拒绝（implicit deny）
身份策略 vs 资源策略 前者挂在身份上（”我能做什么”），后者挂在资源上（”谁能访问我”，如 S3 bucket policy）
最小权限 只给完成任务所需的权限，考试几乎每次都考
MFA 建议全账号开启，root 必须开
Root 账号 只用于开通/账单/救急，日常操作别用；丢失需重置
STS 发放临时凭证的服务，Role 切换底层就是它
IAM Identity Center（原 SSO） 多账号统一登录、对接外部 IdP
Cognito 面向应用最终用户的登录（User Pool 认证、Identity Pool 换 AWS 临时凭证）
Permission Boundary 给身份设”权限天花板”
SCP 组织层限制，作用于账号，不作用于 root 之外的授权细节，也不给权限，只做减法

关键规则：

  • 权限判定顺序：显式拒绝（Deny）优先级最高 > 显式允许 > 默认拒绝。
  • IAM 是全球性服务，不受区域限制。
  • Access Key 泄露 → 立即停用/轮换，用 CloudTrail 查调用记录。
  • 联合身份（企业 AD / SAML / OIDC）→ 用 Role，不用复制一堆 IAM 用户。

3.3 加密与密钥

服务 用途
KMS 托管密钥、信封加密、可审计，默认选项
CloudHSM 专用硬件模块，客户完全掌控密钥（合规要求 FIPS 140-2 Level 3）
ACM 申请/自动续期 TLS 证书，用于 CloudFront/ALB
Secrets Manager 存数据库口令/API Key，支持自动轮换
Systems Manager Parameter Store 存配置与普通密钥，便宜（不自动轮换）
S3 加密 SSE-S3（S3 托管）、SSE-KMS（KMS 托管+审计）、SSE-C（客户自带密钥）、客户端加密

加密两态：静态加密（at rest） 与 传输加密（in transit，TLS），考试常用”satisfy compliance requiring encryption at rest”来筛服务。

3.4 安全服务按用途分组（避免张冠李戴）

用途 服务 一句话识别
威胁检测（发现异常行为） GuardDuty 分析 VPC Flow Logs、DNS、CloudTrail，找恶意活动与挖矿
漏洞扫描 Inspector 扫 EC2/ECR/Lambda 的 CVE 漏洞与配置
敏感数据发现 Macie 用机器学习找 S3 里的 PII（身份证、信用卡）
DDoS 防护 Shield（Standard 免费/Advanced 付费） 网络层/传输层攻击，Advanced 带 24/7 DRT
Web 应用防火墙 WAF 第 7 层，拦 SQL 注入、XSS、按 IP/地理限流
集中防火墙策略 Firewall Manager 多账号统一下发 WAF/Shield/SG 规则
网络层防火墙 Network Firewall VPC 内深度包检测、出入向管控
合规审计报告 Artifact 下载 SOC/ISO/PCI 报告，无额外费用
合规规则评估 Config 记录资源配置变更、判断是否符合规则
API 调用审计 CloudTrail 谁在什么时候做了什么 API 调用
指标与日志监控 CloudWatch 指标、日志、告警、仪表盘
安全态势汇总 Security Hub 聚合各服务告警，对照 CIS/AWS 基线打分
安全事件调查 Detective 图形化回溯”谁、怎么进来的”
最佳实践检查 Trusted Advisor 成本/性能/安全/容错/配额五项检查
密钥/凭据 KMS、CloudHSM、Secrets Manager 见上一节
应用用户认证 Cognito 面向终端用户
目录服务 Directory Service AD 托管、与本地 AD 打通
集中运营平台 Organizations + Control Tower 多账号、SCP、landing zone

3.5 合规与认证常识

  • 常见合规项目：SOC 1/2/3、PCI DSS、HIPAA、GDPR、FedRAMP、ISO 27001、CSA STAR。
  • 拿报告的地方永远是 AWS Artifact（不是 Support，也不是 Trusted Advisor）。
  • AWS 合规是继承式的：你用了托管服务，底层合规由 AWS 承担，但你仍要为自己的配置、数据、访问控制负责。
  • 渗透测试：对自己的资源做安全测试多数情况无需事先申请，但禁止攻击 AWS 基础设施、其他客户、以及拒绝服务类测试；有清单，考前只需记住”允许但有边界”。

四、技术与服务（34%，占比最大）

4.1 计算

服务 定位 关键考点
EC2 云服务器（IaaS） 实例族、购买选项、AMI、User Data
Lambda 无服务器函数 最长 15 分钟、按调用与时长计费、事件驱动、无需管服务器
ECS 容器编排（AWS 自研） 与 Fargate 搭配免管服务器
EKS 托管 Kubernetes 已有 K8s 生态选它
Fargate 无服务器容器运行 不想管 EC2 节点
Elastic Beanstalk PaaS 部署 Web 应用 只传代码，自动建环境，仍可完全控制底层
Lightsail 简化版 VPS，固定月费 小站、预算固定、新手
Batch 批处理作业 大规模计算任务
App Runner 容器化 Web 服务一键上线 最简部署
Outposts / Local Zones / Wavelength 边缘与本地计算 低延迟、数据驻留

EC2 实例族记忆锚点：

族 特点 典型用途
T 系列 通用、突发性能（burstable） 轻负载、开发测试
M 系列 通用均衡 Web 服务器
C 系列 计算优化（Compute） 批处理、编码、高性能计算
R / X 系列 内存优化（RAM） 数据库、缓存、大数据分析
I / D / H 系列 存储优化 高 IOPS、大容量本地盘
G / P / Inf / Trn 加速计算（GPU/推理/训练） 机器学习、图形渲染

六种购买选项（几乎必考，按”省不省、稳不稳、谁适合”记）：

选项 折扣 承诺 适用
On-Demand 按需 无 无 短期、不确定、开发测试
Reserved 预留实例（1/3 年） 明显（Standard 最省、Convertible 可换族） 1 或 3 年 长期稳定运行
Savings Plans 节省计划 高于 RI（承诺每小时用量） 1 或 3 年 用量稳定但实例可能变
Spot 竞价 最高（约 9 折省到 90%） 无，随时可能被回收 可中断任务：批处理、渲染、CI
Dedicated Hosts 专用主机 无固定折扣 按主机 自带许可证 BYOL、强合规
Dedicated Instances 专用实例 — — 物理隔离，但不掌控主机
Capacity Reservation 容量预留 无折扣 按 AZ 预留 保证有容量，不省成本

判据口诀： cheapest 且能中断 → Spot；长期稳定 → RI/Savings Plans；BYOL/合规 → Dedicated Host；保证容量 → Capacity Reservation；其余 → On-Demand。

ELB 四种负载均衡器：

类型 层级 特点
ALB 应用型 第 7 层 HTTP/HTTPS 按路径/主机名路由、支持 WAF、最常用
NLB 网络型 第 4 层 TCP/UDP 极高性能、固定弹性 IP、可直连
GLB 网关型 第 3 层 配合 GWLB 做安全设备接入
CLB 经典型 第 4/7 层 老服务，新项目不用

Auto Scaling：按指标（CPU、请求数、自定义）或计划伸缩；跨 AZ 部署；与 ELB 结合做健康检查替换。

4.2 存储

服务 类型 关键点
S3 对象存储 桶/对象，无限容量，11 个 9 持久性，按量计费
EBS 块存储（挂 EC2） 只能挂同一 AZ 的实例，快照可跨区复制
Instance Store 临时块存储 实例停止/终止即丢数据，性能最高
EFS 文件存储（NFS） Linux 共享、多 AZ、按用量计费
FSx 文件存储家族 FSx for Windows（SMB）、Lustre（高性能计算）、ONTAP/OpenZFS
Storage Gateway 本地-云网关 File（SMB/NFS）、Volume（iSCSI）、Tape（虚拟带库）
Snow 家族 离线传输 Snowcone/Snowball/Snowmobile
AWS Backup 集中备份 跨服务统一策略、合规保留

S3 存储类（按”访问频率 + 检索速度”排）：

存储类 适用 关键约束
S3 Standard 高频访问 基准
S3 Intelligent-Tiering 访问模式不可预测 自动分层，收小额监控费
S3 Standard-IA 低频但需快速取回 存储便宜、取回收费，最短存 30 天
S3 One Zone-IA 低频且可重建 单 AZ，AZ 故障会丢
Glacier Instant Retrieval 归档但要毫秒级取 最短 90 天
Glacier Flexible Retrieval 归档，分钟到小时取回 最短 90 天
Glacier Deep Archive 长期冷备 最便宜，取回最慢，最短 180 天

S3 高频考点：版本控制（Versioning）、生命周期规则（Lifecycle 自动转档/删除）、跨区域复制（CRR）、预签名 URL（临时授权下载）、静态网站托管、Multipart Upload（大文件）、Transfer Acceleration（加速上传）、强一致性读（新对象写入后立即可读）。

4.3 数据库与分析

服务 类型 一句话
RDS 关系型托管 MySQL/PostgreSQL/MariaDB/Oracle/SQL Server，Multi-AZ 是备用不可读
Aurora 云原生关系型 兼容 MySQL/PG，性能更高，6 副本跨 3 AZ，可加只读副本
DynamoDB NoSQL 键值/文档 单表毫秒级、无限扩展、按读写容量或按请求计费；DAX 做内存缓存
Redshift 数据仓库（列式 OLAP） 大规模分析查询、Redshift Spectrum 直接查 S3
ElastiCache 内存缓存 Redis / Memcached，减轻数据库压力
Neptune 图数据库 社交关系、推荐路径
DocumentDB 文档数据库 兼容 MongoDB
Keyspaces 宽列 兼容 Cassandra
OpenSearch 搜索与分析 全文检索、日志分析
Athena Serverless 查询 S3 标准 SQL、按扫描数据量计费，无服务器
Glue ETL + 数据目录 无服务器爬取、转换
EMR Hadoop/Spark 集群 大数据处理
Kinesis 流数据 Data Streams（实时、分片）、Firehose（投递到 S3/Redshift）、Analytics（流上跑 SQL）
MSK 托管 Kafka 已有 Kafka 生态
QuickSight BI 可视化 仪表盘、ML 洞察
Lake Formation 数据湖权限 细粒度访问控制

Multi-AZ vs Read Replica（经典易混）：

对比 Multi-AZ Read Replica 只读副本
目的 高可用/故障自动切换 分担读压力/扩展读性能
副本是否可读 否（standby 不可读） 是
故障切换 自动，秒级 手动提升为主库
跨区域 同区域内 可跨区域

4.4 网络与内容分发

服务 作用 考点
VPC 虚拟私有网络 子网（公有/私有）、路由表、IGW、NAT
Security Group 实例级防火墙 有状态、只允许（无 Deny）、默认拒绝入站
NACL 子网级防火墙 无状态、允许+拒绝、规则按编号顺序匹配
NAT Gateway 私有子网出网 托管、按用量计费；NAT Instance 需自己维护
VPC Peering 两个 VPC 直连 不传递（A-B、B-C 不等于 A-C）
Transit Gateway 中心辐射型互联 多 VPC/多账号/接本地，替代网状 peering
VPC Endpoint 私网访问 AWS 服务 Gateway（S3/DynamoDB，免费）、Interface（PrivateLink，多数服务）
Direct Connect 专线 稳定带宽、低延迟，不加密（需叠加 VPN 或 TLS）
Site-to-Site VPN IPSec 加密隧道 快速建立、走公网
CloudFront CDN 边缘缓存、HTTPS、OAC 保护 S3 源
Global Accelerator 全球加速 静态 Anycast IP、走 AWS 骨干网、TCP/UDP
Route 53 DNS 路由策略：Simple/Weighted/Latency/Failover/Geolocation/Multivalue/Geoproximity
API Gateway API 托管 限流、鉴权、与 Lambda 集成
AppSync GraphQL API 移动端实时数据

CloudFront vs Global Accelerator：缓存内容、减少回源 → CloudFront；不缓存、要 TCP/UDP 低延迟与固定 IP → Global Accelerator。

服务 作用 记忆点

Trusted Advisor 五项检查 成本/性能/安全/容错/配额，付费计划才全开

CloudWatch / CloudTrail / Config 三兄弟辨析（选择题高频）：

  • 要查”谁在凌晨删了安全组” → CloudTrail

服务 模型 用途
SQS Standard 队列，至少一次投递 解耦、削峰，吞吐高

SNS 发布/订阅，推送 一对多通知、短信/邮件
EventBridge 事件总线 事件驱动、按规则路由、接第三方 SaaS
Step Functions 状态机编排 多步业务流程、可视化重试
MQ 托管 ActiveMQ/RabbitMQ 已有 JMS/AMQP 生态

判据：要”任务排队慢慢做、允许重复” → SQS；要”一条消息通知多个订阅者” → SNS；要”按事件内容路由到不同目标” → EventBridge；要”串起多步、有失败重试” → Step Functions。

五、计费与支持（12%）

5.1 计价的三个基本盘

AWS 收费基本围绕三件事：计算（Compute）、存储（Storage）、数据传输（Data Transfer）。

关键规则：

  • 数据传入 AWS 免费，传出收费（Internet 出向按 GB 计费）。
  • 跨 AZ、跨区域传输收费；同 AZ 内网免费。
  • S3 按”存储量 + 请求数 + 取回”三段计费；Glacier 取回最贵。
  • 没有”按用户数”的许可费，除非用 Marketplace 的第三方软件。
  • 免费额度（Free Tier）三类：12 个月免费（如 750 小时 t2.micro）、始终免费（如 Lambda 每月 100 万请求）、试用期（如 SageMaker 试用）。

5.2 成本工具

工具 作用
Cost Explorer 可视化历史成本、按服务/区域/标签下钻、预测
AWS Budgets 设预算与阈值告警（也可监控用量）
Cost Allocation Tags 给资源打标签，分摊成本到部门/项目
Cost and Usage Report（CUR） 最细粒度的账单明细（S3 存放）
Savings Plans / RI 建议 基于历史用量推荐购买方案
Compute Optimizer 规格过大的实例建议降配
Pricing Calculator 上线前估算价格
Billing Conductor 给客户/分部出定制账单（分销场景）

合并账单（Consolidated Billing）：Organizations 下所有账号汇总到付款账号一张账单，共享用量折扣层级（如 S3 阶梯价按总量算），集中付款但成本仍可按账号/标签拆分。

5.3 六种 Support 计划（常考”哪种需求配哪个计划”）

计划 价格（大致） 响应时间 关键能力
Basic 免费 无技术 SLA 24/7 账户与账单客服、文档、论坛、Service Health
Developer 29 美元/月或用量 3%（取高） 一般问题 24 小时内 工作时间邮件、1 个主联系人、技术指导
Business 100 美元/月或用量 10%（取高） 生产系统宕机 4 小时内 24/7 电话/聊天、无限联系人、Trusted Advisor 全量检查
Enterprise On-Ramp 约 5500 美元/月 业务关键 4 小时内 TAM 池、成本优化与架构评审
Enterprise 约 15000 美元/月 业务关键 15 分钟内 专属 TAM、Concierge、基础设施事件管理、 proactive 评审

判据：只要题干出现”生产环境宕机要在几小时内响应””要 TAM””要 Trusted Advisor 全套””要 Concierge” → 直接对应上表；只有账单问题、预算为零 → Basic。

5.4 AWS 组织与合作伙伴

  • Organizations：OU 分层、SCP 限制权限上限、合并账单、集中备份与合规。
  • AWS Partner Network（APN）：Consulting Partner（帮你设计/实施）与 Technology Partner（提供软件/硬件）。
  • AWS Marketplace：第三方软件订阅市场，按需/年付，账单合并。
  • AWS Professional Services：AWS 官方付费咨询团队。

八、备考与考试技巧

复习顺序（按权重倒排，先拿 30 + 34 = 64 分的两大块）：安全（共担责任 + IAM）→ 服务家族（按”计算/存储/数据库/网络/管理”五张表刷）→ 云概念 → 计费与 Support。

四周计划：

周 内容 产出
第 1 周 云概念 + 区域/CAF/迁移 7R 能默画六大优势与六支柱
第 2 周 共担责任 + IAM + 安全服务分组 能说出”这事该谁负责”
第 3 周 五大服务家族 + 易混对照表 每个服务一句话定位
第 4 周 计费/Support + 刷题 + 错题回锅 模拟题稳定 80% 以上

答题技巧：

  • 反向排除：带 always / never / all / only 的选项通常是错的。
  • 双条件题：题干同时给”低成本 + 可中断”才选 Spot，只给低成本可能仍是 On-Demand（因为不能中断）。
  • “最省运维”和”最省钱”经常互斥，看清主语。
  • 多选题只选题干要求数量的，多选一个就错。
  • 不确定时选托管服务（managed）而非自建，选最小权限而非方便权限——这两个方向命中率最高。
